# 存档阵容实验室（实验性本地扩展）

从 FM27 `.fm` 文件只读提取执教球队和指定对手的一线队，为不同双阶段阵型匹配首发，通过已运行的官方 FM Tactics Lab 服务比较战术。

本扩展实现的是“真实阵容 + 明确选择的战术模板 + 统一开赛状态”。当前不支持复现完整职业生涯、自动读取对手 AI 战术或证明全局最优战术。

## 启动

需要 Python 3.12+、官方 v1106 服务和已通过检查的本机 FM27 引擎。先启动官方服务，再在仓库根目录执行：

```powershell
python -m pip install -r career_lab/requirements.txt
python -m career_lab --save-dir '你的游戏存档目录' --tactics-dir '你的战术目录' --data-dir '本地实验数据目录'
```

打开 `http://127.0.0.1:18766`。官方引擎默认地址为 `http://127.0.0.1:18765`，可通过 `--engine` 指定其他本机端口。服务仅监听回环地址。

1. 选择 `.fm` 存档并输入需要读取的对手球队名称。默认名单适用于中文米兰存档；其他语言或球队须填写存档中准确名称。
2. 选择候选 FMF、对手及其测试战术，取消勾选伤停或不使用的球员。
3. 预览自动首发，设定每组主客场场数和随机种子，开始比较。
4. 完成后查看胜平负、胜率和场均积分；第一名可导出到游戏战术目录，导出经过原版解析器回读校验。

5 套候选 × 5 支对手 × 主客场 × 每组 10 场 = 500 场，每套候选 100 场。每套均使用同样的对手与种子。要复测，请换一批种子；排名仅适用于本轮候选和对手。

已保存的 `squads.json` 可通过 `--snapshot` 恢复；`--watch-run` 可以展示由 `core.compare()` 运行的实验目录。

同一数据目录下会记住最近导入和结果路径。重新启动时可不传 `--snapshot`、`--watch-run`。程序退出时尚未完成的自有任务标为中断并保留现场，不自动把部分结果当作完整比较，也不自动重跑比赛。

## 数据与计算边界

- 依赖 MIT 许可的 [fmsave 0.10.0](https://github.com/rhiever/fmsave)。读取前复制稳定快照并校验 SHA-256；不改写源存档，不上传存档。
- fmsave 对部分 FM27 构建借用同 schema 的布局。构建状态与警告保留，严格结构校验失败即停止；不把结构检查当作当前版本所有字段的游戏内验证。
- 读取当前执教球队及指定对手的 `team_slot == 0` 球员；保留入租球员，排除其他队伍的球员。最多选择 23 人比赛名单。
- 52 个非惯用脚属性使用保存的原始 1–100 值；不把四舍五入后的 1–20 显示值乘五。位置熟练度、左右脚、习惯位、年龄、身高、性格、CA、名气分别映射。
- 保留原生比赛背景的槽位 ID，另记录源球员 ID。未读取的体重显式设为门将 80 kg / 其他球员 75 kg。
- 官方引擎强制统一体能、状态、疲劳、士气和磨合。原始体能留在界面供参考，但不声称模拟按今日状态开赛。伤停、停赛与可用性需手动排除。
- 首发匹配使用位置熟练度和位置相关属性的明确启发式，并用子集动态规划求解该评分下的最佳不重复分配。它没有学习原版引擎权重，也不等于模拟意义的最优首发；角色与球员习惯尚未参与首发评分。
- 对手阵容来自存档，对手战术是用户选择的 FMF 模板。定位球用固定的同侧默认套路。没有复现存档全部天气、赛程、训练和临场指挥。
- 每场保留原生结果、日志和校验和。失败立即停止，不计为输赢，不静默重跑。
- 本地 HTTP 页面拒绝跨来源写请求和非回环 Host；读取文件限制在指定存档、战术目录。不要将服务开放到公网。

## 验证

```powershell
python -m unittest career_lab.test_core -v
```

合成测试覆盖原始属性映射、64 位习惯拆分、缺失值拒绝、门将与首发唯一性、排除球员、原生槽位 ID 保留，以及回环地址约束。用户实际存档和游戏原始文件不进入源码或测试夹具。
