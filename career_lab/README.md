# 存档阵容实验室（实验性本地扩展）

从 FM27 `.fm` 文件只读提取执教球队和指定对手的一线队，为不同双阶段阵型匹配首发，通过已运行的官方 FM Tactics Lab 服务比较战术。也可以生成自行设计的阵型、角色和团队指令，再通过初筛与独立复测选择候选。

本扩展实现的是“真实阵容 + 明确选择的战术模板 + 统一开赛状态”。当前不支持复现完整职业生涯、自动读取对手 AI 战术或证明全局最优战术。

## 启动

需要 Python 3.12+、官方 v1106 服务和已通过检查的本机 FM27 引擎。先启动官方服务，再在仓库根目录执行：

```powershell
python -m pip install -r career_lab/requirements.txt
python -m career_lab --save-dir '你的游戏存档目录' --tactics-dir '你的战术目录' --data-dir '本地实验数据目录'
```

打开 `http://127.0.0.1:18766`。官方引擎默认地址为 `http://127.0.0.1:18765`，可通过 `--engine` 指定其他本机端口。服务仅监听回环地址。

1. 选择 `.fm` 存档并输入需要读取的对手球队名称。默认名单适用于中文米兰存档；其他语言或球队须填写存档中准确名称。
2. 选择候选 FMF、对手及其测试战术，取消勾选伤停或不使用的球员。
3. 预览自动首发，设定每组主客场场数和随机种子，开始比较。
4. 完成后查看胜平负、胜率和场均积分；第一名可导出到游戏战术目录，导出经过原版解析器回读校验。

5 套候选 × 5 支对手 × 主客场 × 每组 10 场 = 500 场，每套候选 100 场。每套均使用同样的对手与种子。要复测，请换一批种子；排名仅适用于本轮候选和对手。

已保存的 `squads.json` 可通过 `--snapshot` 恢复；`--watch-run` 可以展示由 `core.compare()` 运行的实验目录。

同一数据目录下会记住最近导入和结果路径。重新启动时可不传 `--snapshot`、`--watch-run`。程序退出时尚未完成的自有任务标为中断并保留现场，不自动把部分结果当作完整比较，也不自动重跑比赛。

## 自设计战术实验

`designs.py` 包含 10 套可编辑的实验假设：4231 控制、4231 快速推进、433 中场控制、433 内收逼抢、3421 稳定结构、3421 翼卫推进、352 双前锋、442 菱形、41230 无锋和 4321 圣诞树。它们从默认中性指令开始，明确设置有球与无球位置、角色和团队指令，没有复制其他作者的 FMF。个人附加指令使用默认值。

生成前依据当前引擎目录检查角色与位置是否合法，导出必须通过原版写入与回读检查。使用指令原生位编号，避免仅凭译名选择指令；例如 `AttackingTransition:54` 是反击。

```powershell
python -m career_lab.designs --tactics-dir '你的战术目录' --output '本地实验目录/designs'
python -m career_lab.search --snapshot '本地实验目录/squads.json' --designs '本地实验目录/designs/designs.json' --opponents-from '之前一次比较/state.json' --reference '你的战术目录/对照战术.fmf' --output '本地实验目录/search-1000'
```

第二条命令复用之前比较中明确选择的对手与战术。在 5 支对手下：

- 初筛：10 套原创 × 5 支对手 × 主客场 × 5 个种子 = 500 场。
- 复测：初筛前四套原创 + 一套既有对照 × 5 支对手 × 主客场 × 10 个新种子 = 500 场。
- 首选按复测胜率、场均积分、净胜球依次排序。初筛成绩不混入最终胜率。每个决赛候选的最终样本量为 100 场，不能写成每套测试了 1000 场。

初筛种子固定为 273000–273004，复测固定为 274000–274009；重复执行相同配置不是新增独立证据。若要开展下一轮独立实验，先在 `search.py` 中更新两组不重叠的种子。当前命令行原创搜索使用所有一线队球员；有伤停或其他排除需求时，可在网页中选择已生成的候选、取消球员并换种子复测。

`protocol.json` 记录方案、分阶段规则、数据校验和和运行代码校验和；`screening/` 与 `validation/` 分别保留完整比赛证据。通过页面启动参数 `--watch-run '本地实验目录/search-1000'` 可显示总进度和复测排名。导出第一名只写入战术文件，游戏内阵容选择还需参考建议首发。

这是有限方案的可复现实验，不是自动学习原版引擎或穷尽所有阵型的优化器。修改 `DESIGNS` 可以开展下一轮设计，但不得把初筛筛选优势当作独立验证结论。

## 数据与计算边界

- 依赖 MIT 许可的 [fmsave 0.10.0](https://github.com/rhiever/fmsave)。读取前复制稳定快照并校验 SHA-256；不改写源存档，不上传存档。
- fmsave 对部分 FM27 构建借用同 schema 的布局。构建状态与警告保留，严格结构校验失败即停止；不把结构检查当作当前版本所有字段的游戏内验证。
- 读取当前执教球队及指定对手的 `team_slot == 0` 球员；保留入租球员，排除其他队伍的球员。最多选择 23 人比赛名单。
- 52 个非惯用脚属性使用保存的原始 1–100 值；不把四舍五入后的 1–20 显示值乘五。位置熟练度、左右脚、习惯位、年龄、身高、性格、CA、名气分别映射。
- 保留原生比赛背景的槽位 ID，另记录源球员 ID。未读取的体重显式设为门将 80 kg / 其他球员 75 kg。
- 官方引擎强制统一体能、状态、疲劳、士气和磨合。原始体能留在界面供参考，但不声称模拟按今日状态开赛。伤停、停赛与可用性需手动排除。
- 首发匹配使用双阶段位置熟练度、位置属性，以及已显式配置的角色属性权重。例如影锋更看重射门和无球跑动，组织者更看重传球和视野；未单独配置的角色回退到位置权重。子集动态规划求解该评分下的最佳不重复分配。它没有学习原版引擎权重，也不等于模拟意义的最优首发；球员习惯未参与首发评分。
- 对手阵容来自存档，对手战术是用户选择的 FMF 模板。定位球用固定的同侧默认套路。没有复现存档全部天气、赛程、训练和临场指挥。
- 每场保留原生结果、日志和校验和。失败立即停止，不计为输赢，不静默重跑。
- 本地 HTTP 页面拒绝跨来源写请求和非回环 Host；读取文件限制在指定存档、战术目录。不要将服务开放到公网。

## 验证

```powershell
python -m unittest career_lab.test_core career_lab.test_search -v
```

合成测试覆盖原始属性映射、64 位习惯拆分、缺失值拒绝、门将与首发唯一性、排除球员、原生槽位 ID 保留、回环地址约束、角色改变选人偏好、两阶段样本分离与失败停止。用户实际存档和游戏原始文件不进入源码或测试夹具。
